# مقدمة في واجهات برمجة التطبيقات REST وبروتوكول HTTP

تمثل واجهة برمجة التطبيقات REST أسلوباً معمارياً لبناء خدمات الويب التي تتواصل عبر بروتوكول HTTP. يُعرَّف كل مورد بمعرّف URI فريد (مثل `/api/courses` أو `/api/quizzes`)، ويتفاعل العميل مع هذه الموارد باستخدام أفعال HTTP القياسية.

## أفعال HTTP الأساسية

- **GET**: جلب بيانات المورد من الخادم دون تعديل حالته، وتُعد عملية آمنة وقابلة للتكرار.
- **POST**: إنشاء مورد جديد على الخادم، مثل تسجيل طالب جديد أو إنشاء مسودة اختبار.
- **PUT / PATCH**: تحديث مورد موجود؛ حيث يستبدل PUT المورد بالكامل بينما يطبّق PATCH تعديلاً جزئياً.
- **DELETE**: حذف مورد محدد من الخادم.

## رموز الحالة الشائعة (Status Codes)

- **200 / 201**: نجاح الطلب أو إنشاء المورد بنجاح.
- **400 Bad Request**: إرسال بيانات غير صالحة من العميل.
- **401 / 403**: فشل التحقق من الهوية أو عدم امتلاك صلاحية الوصول للدور المطلوب.
- **404 Not Found**: المورد المطلوب غير موجود.
